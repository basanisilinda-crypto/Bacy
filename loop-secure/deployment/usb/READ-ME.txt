LOOP SECURE - NEW CUSTOMER USB SETUP

1. Download a fresh setup ZIP for the intended customer from the administrator website.
2. Extract this ZIP into its OWN folder. Keep its files together. No copying into the SDK folder is needed.
3. Connect ONE new/eligible phone by USB, keep it unlocked, and enable USB debugging.
4. Double-click Enroll-Windows.cmd. The helper finds Google Platform Tools or asks you to select adb.exe once. This laptop remembers the selected location.
5. On the phone tap Allow USB debugging. Press a key in the helper if it is waiting to recheck.
6. The helper separately verifies actual device ownership and active administrator status. Only after both are confirmed, tap Connect customer account on the phone and keep internet connected.

First-time laptop preparation only: download and extract Google's Platform Tools for Windows from https://developer.android.com/tools/releases/platform-tools and read the Google terms there. You do not need the full Android SDK. When asked, choose adb.exe inside the extracted platform-tools folder.

Each setup ZIP contains a private one-time enrollment code for ONE customer. The code expires 30 minutes after generation. Do not mix files between customers or share the ZIP. Generate/download a fresh setup if the code expired.

Already-enrolled phones use Update-Windows.cmd from the client-update ZIP instead of this enrollment helper. Retrying an app update does not require a new customer record.

The helper does not reset phones or remove accounts. Android can refuse device ownership on an ineligible/already-managed phone. Check the exact error rather than attempting a bypass.

Once setup and handset tests succeed, disable USB debugging and revoke the laptop's debugging authorization. Actual banking, emergency access, locking and restart behavior must be checked on the handset.

IF THE APP INSTALLS BUT OWNERSHIP FAILS
Installation Success does not mean Android assigned management. If Android says accounts already exist, setup must stop. On the PHONE, check Settings > Accounts (or Passwords and accounts) for Google, email, work and other accounts. Back up/sync data and make sure you know the account passwords before deciding whether to remove any account from this test phone. Account removal is done in phone Settings, never by this helper. Android may still require an eligible new/reset device; do not reset without a backup. After resolving eligibility, download a fresh customer setup ZIP and retry. The helper saves Android's refusal in Enrollment-error.txt.

Always use the FULL current setup ZIP. The new ownership check requires the matching updated client APK. Existing linked accounts are preserved; this helper will not change an already enrolled phone to another customer.

If setup keeps asking for a fresh ZIP, use Ownership-check.txt to see the actual Android ownership-probe response. Repeated downloads do not repair an unreadable account or a denied USB/permission check. Keep the phone unlocked; preserve saved app data when the response says linked=unknown.
