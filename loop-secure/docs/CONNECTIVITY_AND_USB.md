# Connectivity and enrollment update

The managed client has Wi-Fi and Settings actions in account setup, account-loading and customer-home screens. Only verified system handlers for Android Settings/Wi-Fi can join the managed lock-task allowlist; arbitrary third-party settings handlers and the framework chooser are rejected. Banking and emergency access remain available. Wi-Fi configuration restrictions are cleared even when an older signed policy requested them, following the owner's requirement to keep connectivity available.

Supported financing protection remains: reset through Settings, safe boot, adding/switching users, and uninstall of the management app. The client also requests Android's user-control protection against clearing its data or force-stopping it. The management diagnostic reads the applied state. Factory reset through physical buttons/recovery, firmware replacement, and bootloader protection cannot be guaranteed by an ordinary Android device-owner app; those require supported manufacturer/enterprise provisioning facilities. No undocumented OEM-unlock API is used.

Every new Windows enrollment ZIP and code-free update ZIP contains START-HERE.cmd and Prepare-Tools.ps1. After extraction, one Windows launch prepares or finds current official Google ADB tools, remembers the location, checks the exact authorized device, installs the signed APK and either preserves the existing account or verifies device ownership before starting the intended new connection. Tools download over Google HTTPS and are checked against Google's published repository checksum; obsolete ADB protocol clients are skipped. No SDK-folder copying or manual CMD commands are required.

USB debugging/laptop authorization and Android's device-owner eligibility still apply. The helper never resets phones, removes accounts, bypasses another device owner, treats an active admin as device ownership, or overwrites an existing customer. Customer linking uses the existing administrator-recorded consent/audit flow. A DUMP-protected native status provider replaces the fragile ordered-broadcast probe, returns a fresh nonce and ownership/account-presence flags only, and rejects invalid queries and all writes. Unknown/unreadable state stops enrollment.

Android QR payload construction is shared, validates the exact admin component, HTTPS installer URL and URL-safe SHA-256 checksum, and retains compact and legacy bootstrap compatibility. Full provisioning PNGs are independently decoded in the QR check. New/reset eligible phones must use Android's setup provisioning scanner, not a normal web-camera QR reader. Use USB updates for already-enrolled phones. Physical QR/USB/settings/banking compatibility remains a handset acceptance check.

Validation: release builds/lint for all three APKs; Android 11/API 30 and Android 15/API 35 unit checks for system-settings isolation, managed Wi-Fi launch, preservation of reset restrictions and read-only ownership reporting; existing banking/ownership regressions; actual PowerShell parser cases; script syntax; full QR PNG decoding; browser and Cloudflare auth/relay checks; signed-installer/public-download byte verification. Windows driver/device interaction and manufacturer recovery behavior cannot be simulated by these checks.
