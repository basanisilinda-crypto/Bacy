# Failed checkout recovery — 0.16.1

When iKhokha says **Too many payment attempts. Please request a new pay link**, reopening the same exhausted link does not repair it. Close that payment page and open **Make a payment → Get fresh payment link**. In the administrator website, open the intended customer's Manage panel and choose **Replace failed payment link**.

The API fetches the old link's authoritative provider status first. PAID attempts return their confirmation; ambiguous statuses or mismatched amounts/links cannot be replaced automatically. Only a matching UNPAID or provider-confirmed ATTEMPTS_EXCEEDED link can be replaced. The actual failed link was verified directly with iKhokha and returned ATTEMPTS_EXCEEDED with the expected link ID and R300 amount. Unpaid cached checkouts older than 15 minutes also refresh on the next normal Pay online request, so existing 0.16 clients can recover without an immediate APK update. Recently created links have a one-minute replacement cooldown, and the existing per-customer daily creation limit remains. This is deliberate fresh-link recovery, not unlimited retries or a bypass of bank/provider security controls.

Old intents remain available for reconciliation and late signed callbacks, including after a new link becomes active. Every distinct confirmed receipt is credited only once by the existing atomic transaction. Never retry a debited transaction just because a browser page failed; use Check payment status or contact the merchant/provider first.

The new native update separates **Pay by card / online checkout**, **Pay by Instant EFT / Ozow**, **Bank transfer details (manual EFT)**, **Check payment status** and **Get fresh payment link**. The Instant EFT shortcut opens the same correctly attributed iKhokha checkout with a payment-method instruction; it does not invent an Ozow API credential or force an undocumented payment option. Available payment methods and banks are controlled by iKhokha/Ozow. If Instant EFT/Ozow is absent on a fresh checkout, the merchant must ask iKhokha to enable/confirm it. Direct bank transfer details remain a separate manual settlement-review flow.

The trusted hosted provider's exhausted-link message is detected as a boolean only; no card fields, bank credentials or OTP text are read or stored. A Get fresh payment link control appears on checkout recovery. Reported checkout outcomes and verified failure callbacks improve the pending/failure explanation but never grant financial credit. A return-page success flag still requires an independent PAID check.

Version 0.16.1/code 24 is published through the same verified automatic-update channel introduced in 0.16.0. Managed phones on 0.16 can receive it on a scheduled unmetered Wi-Fi check while idle. Android scheduling is not an immediate push guarantee. Older apps still need the one-time updater-capable installation; manufacturer silent-install behavior needs handset acceptance.

Validated: provider fixtures exercise matching UNPAID replacement, paid/ambiguous rejection, stale-link renewal, cooldown, active-pointer replacement and retention of old pending intents for late callbacks. Release build/lint and native regression checks are run before publication. A fresh link is not a completed payment; successful bank verification and provider PAID confirmation still need a real customer checkout.
